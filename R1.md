# MATLAB Batch Run on GitHub Actions

This package runs the same 90 combinations x 100 trials = 9000 trials using multiple GitHub-hosted MATLAB jobs, then merges all per-trial tables and recomputes the final statistics.

## Files

- `a01.m` - your V2 MATLAB experiment with deterministic sharding added.
- `a02.m` - merges shard MAT files, verifies all 9000 unique `(ComboID,Trial)` rows, verifies 90 combos x 100 trials, and creates final CSV/MAT outputs.
- `.github/workflows/dvhop-9000.yml` - GitHub Actions workflow using 12 parallel shard jobs.

## Important privacy/licensing point

For the easiest no-cost MATLAB Actions licensing, use a **public GitHub repository**. A public repository means your MATLAB source is visible to everyone. Do not publish unpublished/confidential research code unless you are comfortable making it public.

For a private repository, MathWorks MATLAB Actions do not automatically license products; a MATLAB batch licensing token or another licensing setup is required.

## Upload and run

1. Create a new GitHub repository.
2. Upload the complete contents of this package **including the `.github` folder**.
3. Make sure the repository contains this exact structure:

```text
repository-root/
  a01.m
  a02.m
  README_RUN_GITHUB.md
  .github/
    workflows/
      dvhop-9000.yml
```

4. Commit the files.
5. Open the repository's **Actions** tab.
6. Choose **MATLAB Batch Run**.
7. Click **Run workflow**.
8. GitHub starts 12 independent MATLAB shard jobs.
9. After all 12 complete, the `merge-results` job automatically downloads and verifies them.
10. Open the completed workflow run and download the artifact named:

```text
DVHOP-FINAL-9000-RESULTS
```

## Final artifact contents

```text
DVHOP_FAST_9000_PER_TRIAL.csv   # 9000 rows
DVHOP_FAST_9000_BY_COMBO.csv    # 90 rows
DVHOP_FAST_9000_OVERALL.csv     # 1 row
DVHOP_FAST_9000_RESULTS.mat
```

## Scientific-result preservation

The global experiment grid remains exactly:

- Areas/nodes: 100/100, 200/200, 500/300
- Communication ranges: 15, 20, 25, 30, 35, 40
- Anchor percentages: 10, 15, 20, 25, 30
- Trials per combination: 100
- Combinations: 90
- Total trials: 9000

Each trial keeps the same deterministic seed formula from your V2 code:

```matlab
seed = uint32(100000 + comboID*1000 + trialNo);
```

Sharding changes only **which GitHub machine executes a trial**. It does not intentionally change the trial's `ComboID`, `Trial`, `Seed`, algorithm settings, or logged scientific metrics.

## Why the merge uses MAT files

Each shard saves its `T` table to a MAT file. The merge step loads those tables directly, which preserves MATLAB variable types better than re-importing CSV text.

Before final output, `a02.m` stops with an error unless it finds:

- exactly 9000 rows,
- no duplicate `(ComboID,Trial)` pair,
- exactly 90 combos,
- exactly 100 trials for every combo,
- Trial numbers 1 through 100 for every ComboID.

Only after those checks pass are the final CSV/MAT files written.

## Changing the number of parallel GitHub jobs

The workflow currently uses 12 shards. If you change the count, update **both** places in `.github/workflows/dvhop-9000.yml`:

```yaml
shard: [0, 1, 2, ..., 11]
```

and

```yaml
RUN_PARTS: '12'
```

For example, for 8 shards use IDs 0 through 7 and set `RUN_PARTS: '8'`.

## Local MATLAB test before the full GitHub run

You can run the V3 file locally without setting environment variables:

```matlab
[T,ByCombo,Overall] = a01;
```

With no shard environment variables it defaults to one shard and therefore runs the full original 9000-trial workload.

To test sharding locally, run a fresh MATLAB session and set, for example:

```matlab
setenv('RUN_PARTS','12');
setenv('RUN_PART','0');
[T,ByCombo,Overall] = a01;
```

That runs only shard 0. Do not merge until all configured shard IDs have been executed.
